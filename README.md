# Точка Перевода Прогресс — платформа бюро переводов

Сайт с каталогом и калькулятором, онлайн-заказ с загрузкой документов и оплатой
по СБП/QR/карте, проверка статуса, личный кабинет, Telegram-бот и Mini App,
CRM-админка (канбан, клиенты, прайс, финансы, отчёты, экспорт) и кабинет переводчика.

Три пункта приёма в Казани — клиент выбирает ближайший при заказе:
ул. Сибирский Тракт, 7/6 · ул. Карла Маркса, 65 · ул. Промысловая, 5, каб. 3.

Переводим **на русский** с 14 языков: туркменский, узбекский, турецкий, азербайджанский,
казахский, киргизский, персидский (фарси), арабский (Ирак, Сирия), английский, немецкий,
французский, испанский, итальянский.

## Промокоды и скидки

CRM → «Промокоды»: сотрудники сами придумывают коды и автоскидки — процент (с потолком) или сумма,
минимальная сумма заказа, период, общий лимит и лимит на клиента, «только первый заказ».
Скидка считается от стоимости услуг со срочностью (без заверения и доставки); из кода и автоскидок
применяется наибольшая. Решает сервер (`/api/promo/quote`, подбор кодов ограничен по IP), клиентам
таблица закрыта RLS; применённая скидка хранится в заказе (`orders.promo_discount`).

## Оплата

- **Онлайн** — СБП, QR или карта (ЮKassa; без ключей работает mock). Для заказов от порога (`prepayment_threshold`,
  по умолчанию 3 000 ₽) и нотариальных — предоплата `prepayment_percent` % (по умолчанию 50), остаток при получении;
  мелкие заказы — 100% онлайн. Правила — `src/lib/payments/policy.ts`, значения — CRM → Настройки.
- **В точке** — клиент выбирает «оплатить в точке» (наличные или карта при сдаче документов): онлайн ничего не платит,
  менеджер отмечает оплату в карточке заказа. Выключается настройкой `pay_in_office_enabled`.
- **Ссылка на оплату из CRM** — остаток или доплата (срочность, доп. страницы; доплата сразу увеличивает стоимость
  заказа). Клиент получает ссылку по Telegram → SMS → email (для гостя — токен на 7 дней), открытую ссылку можно отозвать.
- **Возвраты** — кнопка «Вернуть» у успешного платежа: полный или частичный; через ЮKassa API (статус по вебхуку
  `refund.succeeded`/`refund.canceled` — включите эти события в кабинете ЮKassa), для наличных — фиксация ручного
  возврата. Оплачено = платежи − успешные возвраты; клиенту уходит уведомление. Чеки возврата по 54-ФЗ формирует
  онлайн-касса ЮKassa.

## Проверка перевода клиентом перед печатью

Сотрудник (CRM → заказ → «Проверка перевода» или рабочее место переводчика) загружает перевод
(PDF или картинки страниц; PDF режется на страницы в браузере) и ключевые данные: ФИО, даты, номера.
Клиент получает ссылку (Telegram → SMS → email; гостю — с токеном на 7 дней, вошедшему — «Мои заказы»),
сверяет данные по одному («Верно» / «Исправить»), отмечает ошибки на страницах и либо присылает
замечания, либо подтверждает тремя галочками. Новая версия заменяет прежнюю; клиенту напоминают
через 12 ч. Подтверждение в офисе (с подписью клиента) отмечает менеджер.

- Страницы отдаются только через сервер, с водяным знаком в пикселях (номер заказа, имя, время) и красной
  плашкой «не является копией»; чистая страница и оригинал в браузер не попадают, ссылок на файл нет.
  Браузер не позволяет запретить скриншот — это сдерживание и след для разбора, а не гарантия.
- Решение фиксируется: время, IP, устройство, номер версии, SHA-256 содержимого, галочки; журнал — только менеджерам.
- Через 24 ч без ответа в CRM видно «можно печатать на свой риск» (бумагу клиент проверит при получении).
- Страницы лежат в закрытом пути `proofs/…` бакета; удаляются retention-cron вместе с файлами заказа.
- Воркер разбора PDF — `public/pdf.worker.min.mjs` (копия из `pdfjs-dist@4.10.38`; при обновлении пакета скопируйте заново).
- Для водяных знаков нужен шрифт с кириллицей: в Docker-образе ставится `ttf-dejavu`.

## Быстрый старт (локально)

Нужны **Node.js ≥ 20**, **pnpm 9** и проект **Supabase** (облачный бесплатный
или локальный через Supabase CLI). Ключи ЮKassa, SMS, SMTP и Telegram не нужны —
работают mock-драйверы.

```bash
pnpm install
cp .env.local.example .env.local   # вставьте ключи Supabase и DATABASE_URL
pnpm db:push                       # схема, RLS, триггеры, прайс (24 услуги), настройки
pnpm db:seed                       # демо-пользователи всех ролей и заказы
pnpm dev                           # http://localhost:3000
```

Где взять значения для `.env.local` (Supabase Dashboard → Project Settings):

| Переменная | Где |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | API → Project URL / anon public |
| `SUPABASE_SERVICE_ROLE_KEY` | API → service_role (только сервер!) |
| `DATABASE_URL` | Database → Connection string → URI (Session pooler) |

Локальный Supabase (нужен Docker Desktop): `npx supabase start` — миграции применятся сами.
Порты перенесены на 5442x, т.к. Windows резервирует 54308–54407:
API `http://127.0.0.1:54421`, БД `postgresql://postgres:postgres@127.0.0.1:54422/postgres`,
Studio `http://127.0.0.1:54423`, почта (Mailpit) `http://127.0.0.1:54424`; ключи — `npx supabase status`.

## Чек-лист запуска в продакшен

1. **Supabase** в регионе, допустимом по 152-ФЗ (self-hosted в Yandex Cloud или managed — см. `docs/152-FZ.md`); включить PITR/бэкапы.
2. `pnpm db:push` против продакшен-БД; **не** запускать `db:seed`.
3. Заполнить реальные телефон и email в `src/lib/config/constants.ts` и настройку `company` (админка → Настройки); часы работы и телефоны точек — админка → Точки.
4. Секреты окружения: `SUPABASE_SERVICE_ROLE_KEY`, `ORDER_ACCESS_SECRET` (`openssl rand -hex 32`), `CRON_SECRET`, `TELEGRAM_WEBHOOK_SECRET`.
5. ЮKassa: `PAYMENT_PROVIDER=yookassa`, `YOOKASSA_SHOP_ID/SECRET_KEY`; в кабинете ЮKassa — HTTP-уведомления на `https://<домен>/api/webhooks/payment` (события `payment.succeeded`, `payment.canceled`); при онлайн-кассе — `YOOKASSA_SEND_RECEIPT=true`.
6. Telegram: токен @BotFather → `pnpm tg:set-webhook`; в @BotFather → Bot Settings → Configure Mini App → URL `https://<домен>/tg`.
7. SMS.ru и SMTP — ключи; callback SMS.ru: `https://<домен>/api/webhooks/sms?secret=<SMSRU_CALLBACK_SECRET>`.
8. Supabase Auth → URL Configuration: Site URL = домен, Redirect URLs: `https://<домен>/auth/callback`.
9. Cron (раз в час `/api/cron/deadlines`, раз в 15 мин `POST /api/notifications`, раз в сутки `/api/cron/retention`) с заголовком `Authorization: Bearer <CRON_SECRET>`.
10. Выдать роли сотрудникам: администратор регистрируется на сайте, роль `admin` выставляется SQL-запросом один раз (см. `docs/OPERATIONS.md`), дальше роли — в админке «Исполнители».
11. Проверка: `GET /api/health` → `database: "ok"`; тестовый заказ на 1 ₽-услугу и возврат в ЮKassa.

## Известные ограничения

- Исходный логотип — 240×240 px: аватар бота и OG-картинка апскейлены. При появлении
  вектора или PNG ≥ 1024 px положите его вместо JPG и выполните `pnpm brand:assets`.
- Стоимость нотариального заверения и доставки по умолчанию 0 ₽ («уточняет менеджер») —
  задайте реальные значения в админке → Настройки.
- Рейт-лимиты хранятся в БД (`rate_limit_hit`), при её недоступности — в памяти процесса.
- ИИ-функции (YandexGPT/GigaChat) — заглушки этапа 2 (`AI_PROVIDER=off`).

Подробности — в [`docs/`](docs/).
