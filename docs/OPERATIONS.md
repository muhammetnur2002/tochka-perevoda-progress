# Регламент работы (менеджер, переводчик, администратор)

## Первый администратор

1. Зарегистрируйтесь на сайте (`/register`) своим email.
2. Один раз выполните в Supabase SQL Editor:
   ```sql
   update public.users set role = 'admin' where email = 'you@example.ru';
   ```
3. Дальнейшие роли выдаются в CRM: **Исполнители → «Выдать роль»** по email
   зарегистрированного сотрудника (переводчик, нотариус, печать, менеджер).

## Менеджер — день в CRM (`/admin`)

1. **Дашборд**: новые заказы, сроки < 24 ч, «не забрали > 3 дней».
2. **Заказы (канбан)**: новый заказ появляется сам (звук + всплывающее уведомление,
   плюс сообщение в Telegram). Перетащите карточку или нажмите «→», чтобы
   сменить статус; клиенту уходит уведомление (Telegram → SMS → email).
   Фильтры: срок < 24 ч, просроченные, не оплаченные, из Telegram, услуга, исполнитель.
3. **Карточка заказа**: клиент, позиции и суммы, файлы (скачивание по ссылке на 5 минут),
   чат с клиентом, история. Справа — статус с комментарием, срок, назначение
   исполнителя (в скобках загрузка: активные задачи / лимит), ручная отметка оплаты
   (наличные, терминал, счёт), загрузка готового перевода или чека.
4. **Цикл заказа**: Новый → (оплата) Подтверждён → назначить переводчика → В работе →
   переводчик нажал «Готово» (вам придёт Telegram) → проверить файл → Готов
   (клиент получит «можно забирать») → Выдан при выдаче → Завершён.
5. **Финансы**: выручка, долги, платежи; экспорт в Excel/CSV для бухгалтерии.
6. **Услуги и цены**: правка цены, срока, скрытие услуги. Уже оформленные заказы
   хранят цену на момент заказа. Все правки — в журнале аудита.
7. **Настройки**: коэффициенты срочности, цена заверения и доставки, % предоплаты,
   праздники (производственный календарь), уведомления, срок хранения файлов.

Telegram-команды для менеджеров (Telegram привязан к профилю или chat id в
`TELEGRAM_MANAGER_CHAT_IDS`): `/new` — новые заказы, `/deadline` — горящие сроки,
`/take ТП-2026-000123` — взять заказ (переводит new → confirmed).

## Переводчик (`/workspace`)

Список задач со сроками (красным — меньше суток). В задаче: исходники, комментарий
клиента, направление перевода. «Взять в работу» → загрузить файл перевода
(перетаскиванием) → «Готово — передать менеджеру». Если задача не подходит —
«Отказаться», менеджер получит уведомление.

## Клиент

Сайт: калькулятор → оформление (фото документа с телефона, согласие) → оплата
СБП/QR/картой → номер заказа. Статус — по номеру и телефону на `/status`, в
личном кабинете или в Telegram. Повтор заказа — кнопка «Повторить» в кабинете.

## Инциденты

| Симптом | Проверка |
|---|---|
| Не приходят оплаты | ЮKassa → HTTP-уведомления (URL, события); `/api/health`; логи «Вебхук платежа» |
| Нет уведомлений клиентам | таблица `notifications` (status = failed, last_error); ключи SMS.ru/SMTP; бот заблокирован клиентом |
| Клиент не видит заказ в кабинете | телефон в профиле не подтверждён — «Профиль → Получить код» |
| Сбой БД | восстановление из `scripts/backup.sh` или PITR |
