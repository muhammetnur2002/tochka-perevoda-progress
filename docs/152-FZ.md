# Персональные данные (152-ФЗ)

> Документ описывает технические меры платформы. Юридические документы
> (политика, согласие, уведомление Роскомнадзора об обработке ПД) должен
> утвердить оператор — бюро «Точка Перевода Прогресс».

## Какие ПД обрабатываются

ФИО, телефон, email, Telegram ID/username, ИНН (для юрлиц), адрес доставки,
**содержимое документов** (паспорта, дипломы, справки — в т.ч. специальные
категории в медицинских документах), IP и User-Agent при даче согласия.

## Меры в платформе

| Требование | Реализация |
|---|---|
| Согласие до обработки | обязательный чекбокс при оформлении; запись в `consents` (версия документа, время, IP, UA) |
| Локализация в РФ | рекомендуемый вариант — Supabase self-hosted и Object Storage в Yandex Cloud (ru-central1), см. `DEPLOY-YANDEX-CLOUD.md` |
| Минимизация доступа | RLS: клиент — свои заказы, исполнитель — только назначенные, менеджер — все; аудит читает только админ |
| Защита файлов | приватный бакет, путь `orders/{order_id}/…`, ссылки на 5 минут, SSE в Object Storage, проверка сигнатур при загрузке |
| Журналирование | `audit_log` (триггеры), `status_history`, `notifications` |
| Срок хранения | cron `/api/cron/retention` удаляет файлы закрытых заказов старше `file_retention_days` (по умолчанию 90) |
| Права субъекта | `/account/data`: выгрузка всех ПД (JSON) и удаление (файлы удаляются, карточки обезличиваются, аккаунт удаляется; финансовые записи сохраняются обезличенно) |
| Привязка заказов к аккаунту | только после подтверждения телефона (SMS-код или контакт Telegram) |
| Транспорт | HTTPS + HSTS, CSP, защищённые cookie сессии |
| Резервные копии | `scripts/backup.sh` (pg_dump) + PITR; копии содержат ПД — хранить в РФ, шифровать |

## Что сделать оператору

1. Утвердить тексты `/legal/privacy`, `/legal/consent`, `/legal/terms` (шаблоны в коде),
   при изменении — поднять `CONSENT_VERSION` в `src/lib/config/constants.ts`.
2. Направить уведомление в Роскомнадзор об обработке ПД.
3. Назначить ответственного за организацию обработки ПД.
4. Выбрать размещение БД и файлов в РФ (см. таблицу вариантов в деплое).
5. Определить сроки хранения документов и выставить `file_retention_days`.
6. Не подключать иностранную аналитику; Яндекс.Метрика — по согласию.

## Шифрование «на уровне приложения» (этап 2)

Сейчас: приватное хранилище + SSE + короткие подписанные ссылки. Опционально —
AES-256-GCM шифрование файлов на сервере перед загрузкой с ключом в Yandex
Lockbox/KMS (feature-flag, см. `ROADMAP.md`).
